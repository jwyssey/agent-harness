# PLAYBOOK — 표 · 센서 · 시계열 데이터

과제가 표 데이터(센서값, 공정 기록, 로그)로 예측 · 탐지를 하라고 할 때만 연다. 이 대응을 하루 흐름에 적용한 예는 [WALKTHROUGH.md](WALKTHROUGH.md). 사람이 보는 참고표다. 스킬이 아니어서 에이전트가 저절로 읽지 않는다. 필요한 줄을 지시에 옮겨 쓴다.

## 0. 먼저 5분: 데이터 모양 보기

Codex 에 보낸다:
```
[데이터 모양] 코드는 고치지 마. data/ 의 표마다 행 수 n, 열 수 p, 타깃 분포(회귀면 요약, 분류면 클래스별 건수),
시간 · 그룹으로 보이는 열(날짜, 장비, 챔버, 로트, 웨이퍼, 레시피), 결측 비율이 높은 열, 상수 열, 완전히 같은 열 묶음을 표로.
한 행이 무엇의 단위인지(웨이퍼 · 로트 · 런 · 시점) 추정과 근거도.
```
결과로 아래 1번 표에서 상황을 고른다. 한 행의 단위와 라벨이 정해지는 시점은 담당자에게 확인한다.

## 1. 상황별 대응

| 상황 | 대략의 기준 | 무엇이 위험한가 | 기본 대응 |
|---|---|---|---|
| **small n** (변수에 비해 표본이 적다) | n 이 p 의 10배 미만, 또는 n 이 수백 이하 | 과적합. 분할 하나로 잰 점수가 우연에 크게 흔들린다 | 반복 CV(5-fold × 3~5회)로 평균과 범위를 적는다. 모델 선택까지 하면 Nested CV. 강한 규제(Ridge · ElasticNet · PLS), 부스팅은 얕게 · 규제 강하게. 변수 선택은 CV 안에서만 |
| **large p, large n** (변수도 표본도 많다) | p 수백 이상, n 수만 이상 | 시간 · 메모리. 잡음 변수와 중복 변수 | 열 정리(상수 · 중복 · 결측 많은 열 · 상관 0.99 이상 묶음에서 하나만) → LightGBM · XGBoost(열 샘플링, 조기 종료). 개발은 표본 10~20% 로 5분 안에, 최종만 전체. float32, 필요한 열만 읽기 |
| **고차원 + 변수끼리 상관 큼** (센서 다중공선성) | 같은 물리량을 여러 센서가 잰다 | 선형 계수가 불안정, 중요도가 상관 변수끼리 나뉜다 | 선형 모델에는 PCA · PLS 를 학습 fold 안에서만 fit. 트리 모델은 원래 변수 그대로 둔다. 중요도는 상관 묶음 단위로 해석한다 |
| **불균형** (불량 · 이상이 드물다) | 소수 클래스가 10% 미만 | 정확도가 높아도 쓸모없다(전부 정상이라고 해도 95%) | 정확도 금지. PR-AUC(AP), 정해진 오경보 수준에서의 재현율, **놓친 건수 / 전체 불량 수**로 적는다. class weight · `scale_pos_weight`. 판정 임계값은 OOF 예측에서 담당자가 말한 비용으로 정한다. SMOTE 같은 합성은 기본으로 쓰지 않는다 |
| **시계열 트레이스** (런 · 스텝마다 값이 시간에 따라 찍힘) | 한 웨이퍼 · 런이 여러 행 | 행 단위로 섞으면 같은 런이 학습 · 평가 양쪽에 들어가 누수 | 런(웨이퍼) 단위로 요약 특성을 만든다: 스텝별 평균 · 표준편차 · 최소 · 최대 · 기울기 · 구간 길이. 분할은 시간순이나 장비 · 로트 그룹 단위. 원래 파형이 꼭 필요할 때만 시계열 모델(`--with ml` 의 aeon) |

여러 상황이 겹치면 위험이 큰 쪽부터 막는다: **누수 → 평가 분산 → 불균형 → 시간 · 메모리** 순이다.

## 2. 어느 상황이든 지키는 검증 규칙

- **전처리는 파이프라인 안에서 학습 fold 에만 fit 한다.** 스케일링 · 결측 대체 · 변수 선택 · PCA 를 전체 데이터에 먼저 하면 평가가 새어 점수가 부풀어 보인다.
- **분할 단위는 시간 > 그룹 > 무작위 순으로 고른다.** 같은 로트 · 웨이퍼 · 런이 학습과 평가 양쪽에 있으면 누수다. 장비 정비나 레시피 변경 시점을 넘는 분할이면 그 사실을 한계에 적는다.
- **베이스라인 두 개를 먼저 찍는다.** 평균값 또는 다수 클래스, 그리고 현행 방식(관리 한계선 같은 지금 쓰는 규칙). 모든 숫자는 이 둘 대비로 말한다.
- **R² 가 음수면 평균만 찍는 것보다 못하다는 뜻이다.** 모델을 바꾸기 전에 타깃 정의 · 분할 · 행 단위 · 누수부터 의심한다.
- **탐색은 시간을 정해 둔다.** 넓은 그리드 대신 기본값 + 규제 세기 몇 개. 한 번 돌리는 데 5분이 넘으면 개발용 표본을 줄인다(고정 평가는 그대로).
- **앙상블은 마지막에, 상위 두세 개만.** 약한 모델을 섞으면 평균이 오히려 떨어진다.

## 3. 시간이 없을 때 모델 순서

1. 베이스라인: 평균 · 다수 클래스, 현행 규칙
2. 규제 선형: Ridge · ElasticNet · 로지스틱(스케일링 포함). 빠르고 설명하기 쉽다
3. 그래디언트 부스팅: LightGBM · XGBoost. 범주형 열이 많으면 CatBoost
4. (시간이 남으면) 상위 두 개 확률 평균

각 단계 결과를 `RESULTS.md` 에 한 행씩 남긴다. 다음 단계가 이전보다 나을 때만 넘어간다.

## 4. Codex 에 보내는 한 줄 (상황별)

```
[small n] 표본이 n=___ 이고 변수가 ___ 개라 분할 하나로는 믿을 수 없다. 같은 반복 5-fold CV(5회, 같은 seed)로
Ridge · ElasticNet · CatBoost(얕게) 를 비교하고, 전처리는 파이프라인 안에서만 해. RESULTS.md 에 평균과 최소~최대를 적어.
```
```
[large p · large n] 행이 ___ 만, 열이 ___ 개라 시간이 문제다. 상수 · 중복 · 결측 많은 열을 학습 구간 기준으로 정리한 뒤
LightGBM 을 조기 종료로 돌려. 개발은 학습 구간의 20% 표본으로 5분 안에, 최종 한 번만 전체로. 정리 전후 열 수를 보고해.
```
```
[불균형] 불량이 ___ / ___ 건이라 정확도는 쓰지 않는다. AP 와 '놓친 불량 건수 / 전체 불량' 을 같이 적고,
임계값은 OOF 예측에서 담당자가 말한 기준(___)으로 정해. 합성 샘플은 만들지 마.
```
```
[트레이스] 한 런이 여러 행이라 런 단위로 요약 특성(스텝별 평균 · 표준편차 · 최소 · 최대 · 기울기)을 만들고,
분할은 ___(시간 · 장비 · 로트) 단위로 해. 같은 런이 학습과 평가에 같이 들어가지 않는지 확인해서 보고해.
```

## 5. 설명할 때 (발표 · 질의)

- **왜 이 모델인가**: "규제 선형 대비 ___ 나아졌고, 표본이 n 이라 반복 CV 로 확인했다." 단일 점수 하나로 말하지 않는다.
- **무엇이 중요했나**: permutation importance 나 SHAP 상위 몇 개. 상관이 큰 센서는 묶어서 말하고, 현장 의미는 담당자에게 확인한 문장으로.
- **한계**: 표본 수, 분할이 넘지 못한 조건(정비 · 레시피 변경), 시간이 지나면 분포가 바뀔 수 있다는 점과 그때 다시 볼 기준.

## 6. 담당자에게 물을 데이터 질문

한 행은 무엇의 단위인가(웨이퍼 · 로트 · 런) / 라벨은 언제 정해지나(계측이 늦게 나오면 예측 시점에 쓸 수 없는 열이 생긴다) / 장비 · 챔버 · 레시피 열의 뜻 / 정비나 레시피가 바뀐 시점 / 불량을 놓치는 것과 잘못 울리는 것 중 무엇이 더 비싼가

필요한 라이브러리 사용법은 `./install.sh --with ml`(scikit-learn · shap · statsmodels · aeon 스킬)로 켠다. 과제를 읽고 이 도구를 쓰기로 정한 뒤에만.
