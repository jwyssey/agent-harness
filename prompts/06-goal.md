# 06 구현 goal

- **언제**: 마일스톤마다. 완료 조건이 검사로 정해지는 묶음에만 쓴다("전부 만들어"는 쓰지 않는다).
- **먼저 손으로**: 이유 칸. 담당자 답 · RESULTS.md 행 · 가정 중 무엇 때문에 이 일을 하는지.
- **도는 동안**: `git diff --stat` → 핵심 함수 읽기, PLAN · DECISIONS 정리, 담당자 질문.

```
/goal 목표: ___ (마일스톤 N)
이유: ___ (담당자 답 · RESULTS.md 행 · 가정 중 무엇 때문에 이걸 하나)
완료 조건: ① ./check.sh 통과 ② eval/run.py 결과를 RESULTS.md에 한 행 추가
③ ARCHITECTURE.md의 의존성 · 상태 소유 · 요청 흐름을 실제 파일:함수로 갱신
범위: ___ 만. eval/ · data/split.json · tests/ 의 기존 검사는 고치지 않는다. 상태 변경은 ___ 모듈에서만.
패키지 설치가 필요하면 알려만 줘. 요구에 없는 방어 코드 · 추상화는 넣지 말고 제안만 해.
끝나면: 요구 항목별 구현 위치 / 테스트 / 미구현을 표로 보고하고 멈춰.
```

- **v0** 의 완료 조건에는 "예시 입력 하나로 사용자 화면에 결과가 뜬다"와 "성과 화면이 RESULTS.md를 읽어 표시한다"를 넣는다.
- **개선** goal 은 가설 하나만: "___ (현장 요인) 때문에 ___ 가 틀린다 → ___ 하면 현장 KPI가 오른다". 모델을 바꾸기 전에 현장 요인 반영을 먼저 의심한다.
- 일반 지시도 "X 해"가 아니라 "Y 때문에 X 해"로 쓴다.
