# 08 요청 한 건 추적 (예측 → 실행)

- **언제**: v0 직후와 최종 수정 직후. 5~10분.
- **목적**: 구조를 내 말로 설명할 수 있는지 확인한다. 막히면 구조를 더 단순하게 한다.
- **스킬**: `$learning-opportunities` 가 같은 종류의 연습(예측 → 관찰, 경로 따라가기)을 진행해 준다. 길게 제안하면 "5분짜리 하나만"이라고 답한다.

순서:
1. **AI 없이** ARCHITECTURE.md '요청 한 건의 흐름'을 보고 입력부터 화면까지 90초 안에 머릿속으로 설명해 본다.
2. 상태 변화 하나를 **먼저 예측해 적는다**: "___ 를 입력하면 ___ 파일 / 세션 값이 ___ 로 바뀐다."
3. 실제로 실행해 본다. 예측과 다르면 그 함수를 연다.
4. 그 다음에만 아래를 보낸다.

```
[추적] 코드는 고치지 마.
[내 설명] 요청이 들어오면 ___ → ___ → ___ 순서로 흐르고, ___ 는 ___ 만 바꾼다고 이해했다.
내 설명에서 실제 코드와 다른 곳만 파일:함수로 짚어줘. 맞는 부분은 반복하지 마.
```
