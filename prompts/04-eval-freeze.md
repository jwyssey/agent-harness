# 04 평가 고정

- **언제**: KPI · 가드레일 · 분할 단위를 정한 직후. 모델을 고치기 전.
- **먼저 손으로**: PLAN.md 5번(분할 단위와 이유, 현행 방식)을 채운다.
- **스킬**: 목표 문장이 흐리면 `$define-goal 이 목표 문장만 고쳐 줘. goal은 만들지 마.` 로 다듬는다.

```
/goal eval/ 를 만든다.
이유: 개선 여부를 같은 기준으로 재야 하고, 구현 중에 평가가 바뀌면 숫자를 믿을 수 없기 때문이다.
완료 조건: ① eval/run.py 가 PLAN.md의 모델 지표 · 가드레일과, 계산할 수 있으면 현장 KPI 추정치를 계산한다
② 분할은 PLAN.md의 단위(시간 · 그룹)로 하고 data/split.json 에 고정한다
③ 현행 방식과 베이스라인 결과를 RESULTS.md 첫 두 행에 적는다(표본 수와 양성 수 포함)
④ eval/* 와 data/split.json 의 sha256 을 eval.sha256 에 저장하고, PLAN.md 5번 '검증 명령:' 줄에 평가 실행 명령을 적어 ./check.sh 가 통과한다
범위: 모델 개선은 하지 않는다. 끝나면 숫자와 만든 파일을 보고하고 멈춰.
```

- 끝나면 **커밋하고 그 해시를 PLAN.md의 `eval 고정 커밋:` 줄에 적는다.** `check.sh`와 R1이 그 커밋 이후의 변경을 본다(해시 파일만으로는 다시 찍으면 통과한다).
- 담당자 답으로 기준이 정당하게 바뀌면: 평가를 고치고 → 새 커밋 → PLAN.md에 `eval 고정 커밋: ___ (v2) — 이유: ___` 새 줄 → RESULTS.md는 새 버전으로 현행 · 베이스라인부터 다시 찍는다.
- 예측 과제가 아니면 `eval/run.py` 자리에 과제 산출물에 맞는 검증 명령과 고정 사례(입력 → 기대 결과)를 둔다. 분할과 양성 수는 예측 과제에만 적는다(RUNBOOK 7번).
- 분할 파일을 내가 직접 열어 한 번 본다: 평가 구간이 학습 구간보다 뒤인가, 같은 그룹이 양쪽에 없는가.
