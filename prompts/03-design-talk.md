# 03 설계 대화

- **언제**: KPI 사슬을 확정한 뒤, 구조를 정하기 전.
- **먼저 손으로**: 내가 생각한 구조를 한 줄(`ui → service → model/data`)로.
- **원칙**: 스택은 과제가 준 것을 따른다. DB는 요구될 때만. 상태를 바꾸는 곳은 한 모듈.

```
[설계 대화] 코드는 쓰지 마.
[내 생각] 나는 ___ 구조로 가려 한다. 이유는 ___ 이다.
PLAN.md의 요구 · KPI 사슬을 보고
① 구조: 모듈 나누기 2안과 각 안의 의존성 방향 · 상태 소유
② 화면: 요구 항목마다 사용자 화면의 어디에 보이나(실패 · 대체 상태 표시 포함)
③ 문제 될 부분: 요구에 비해 과한 것, 깨지기 쉬운 곳 3개
내 안에서 틀린 곳이 있으면 먼저 짚어줘. 고르는 건 내가 한다.
```

- 고른 안과 버린 안을 DECISIONS.md에 한 줄로. ARCHITECTURE.md의 의존성 방향과 상태 소유 표 뼈대를 이때 쓴다.
