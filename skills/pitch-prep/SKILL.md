# pitch-prep

발표와 답변은 사용자가 한다. 이 스킬은 근거를 모으고 빈 곳을 찾는다. 대본을 대신 쓰지 않는다.

## 입력

- 인자: 발표 시간(분)과 듣는 사람. 인자에도 `PLAN.md` 에도 없으면 한 번만 묻는다.
- 읽을 파일: `PLAN.md` · `RESULTS.md` · `DECISIONS.md` · `ARCHITECTURE.md`, 있으면 `PITCH.md`. 없는 파일은 건너뛰고 없다고 알린다.
- 코드는 고치지 않는다. 검사 · 평가도 다시 돌리지 않는다. 구현에 관한 주장은 관련 코드를 읽어 기록과 대조하고, 실행해야 알 수 있는 것은 '미확인'으로 표시한다.

## 1. 뼈대 (기본 동작)

`PITCH.md` 의 빈칸을 채운다(없으면 아래 순서로 새로 만든다). 사용자가 이미 써 둔 문장은 바꾸지 말고 바꿀 점을 따로 제안한다. 완성된 문장이 아니라 말의 뼈대를 칸마다 한 줄씩 쓴다.

1. 현장 문제 — 누가, 무엇 때문에, 어떤 판단을 되풀이하나
2. 고른 목표와 제약 — 과제 원문이나 담당자 답을 인용한다. 확인하지 못한 판단은 가정으로 표시한다
3. 시연 순서 — 예시 입력 하나로 결과와 그 근거, 다음 행동까지
4. 현행 대비 결과 — `RESULTS.md` 의 행을 그대로 옮긴다
5. 검증과 내 판단 — 평가를 어떻게 고정했나, 사용자가 직접 바꾼 결정 하나
6. 한계와 다음 확인

지킬 것:

- 성과 숫자는 `RESULTS.md` 에 있는 것만 쓰고 어느 행인지 적는다. 요구 수치와 현행값은 과제 원문 · 담당자 답을 출처로 쓴다. 없는 숫자는 만들지 않고 "근거 없음"으로 표시한다. 드문 사건은 비율 대신 건수와 분모로 쓴다.
- 연습 데이터로 보인 것과 현장에서 입증한 것을 구분해 적는다.
- 시간이 짧으면 칸을 줄인다. 1분이면 문제 · 핵심 동작 · 결과와 고른 이유 · 한계를 한 줄씩만 남긴다.
- 끝에 "근거가 비어 있는 주장" 목록을 따로 보고한다.

## 2. 질문 연습 (인자에 `quiz` 가 있거나 요청받았을 때)

- 이 저장소를 처음 보는 청중의 입장에서 가장 약한 지점부터 묻는다. 한 번에 하나만 묻고 답을 기다린다.
- 사용자의 답을 파일(파일:함수, `RESULTS.md` 행, `DECISIONS.md` 줄)과 대조해 틀린 곳과 빠진 곳만 짚는다. 모범 답안을 대신 쓰지 않는다.
- 권하는 답의 순서는 "지금 구현된 사실 → 이유 → 한계와 다음 확인"이다. 질문의 전제가 구현과 다르면 그 차이부터 말하게 한다.
- 구조를 고른 이유 · 실패 조건 · 사용자가 직접 한 판단을 먼저 묻는다. 다섯 문항을 마치거나, 정한 연습 시간이 끝나거나, 사용자가 멈추라고 하면 끝낸다. 막힌 질문은 `PITCH.md` 의 질문 표에 근거 위치와 함께 적는다.
